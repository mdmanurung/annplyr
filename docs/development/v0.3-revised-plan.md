## 1. Release objective and boundaries

Deliver an intentionally breaking v0.3.0 release that:

1. improves measured runtime or peak memory in the matrix-projection,
   grouped-execution, and metadata-evaluation families;
2. adds persistent tidyverse-style grouping;
3. gives every AnnData-returning operation predictable ownership behavior;
4. projects selected matrix columns before pandas conversion and rejects
   materialization budgets before any matrix read;
5. documents the complete public contract and v0.2 migration path.

Keep typed error classes and the `summarize`/`summarise` aliases. Exact dplyr
parity, lazy evaluation of arbitrary Narwhals expressions, shared-storage
shallow copies, biological analysis helpers, PyPI publication, GitHub release
creation, and bulk notebook execution are out of scope.

Stable Python 3.12, 3.13, and 3.14 jobs are blocking. The prerelease-dependency
job remains advisory.

## 2. Frozen public API contract

Create `docs/development/api-contract-v0.3.md` before changing behavior. Its
inventory must mechanically cover every public accessor method, every public
`GroupedAnnData` method and introspection operation, and relevant exported

### 2.1 Ownership

Shape-changing or axis-order-changing verbs default to `copy=True`:

- `filter`, `select`, `arrange`, `distinct`;
- `slice`, `slice_head`, `slice_tail`, `slice_min`, `slice_max`, and
  `slice_sample`;
- `left_join`, `inner_join`, `right_join`, `full_join`, `semi_join`, and
  `anti_join`.

`copy=True` returns an independent AnnData object with no mutable storage alias
through `X`, layers, raw, `obsm`, `varm`, `obsp`, or `varp`. On backed input it
returns an independent in-memory object containing the selected aligned data.
`copy=False` never mutates the input during the call; it may return an AnnData
view or a materialized AnnData object. AnnData-returning verbs preserve the
input sparse storage format.

Same-shape mutations expose `inplace=False`, remove obsolete `copy=`, and
validate fully before the first write:

- `mutate`, `rename`, `rename_with`, `relocate`;
- `add_count`, `add_tally`, and `add_sample_meta`;
- `rename_obs_names`, `rename_var_names`, `replace_name_suffix`, and
  `add_name_prefix`;
- `store_palette`.

`inplace=False` returns an independent object. `inplace=True` mutates and
returns the identical AnnData instance. This identity rule also covers
`relocate(x=...)` and `add_count(sort=True)`/`add_tally(sort=True)`: centralize
the necessary in-place axis reorder behind a narrow compatibility helper using
AnnData's in-place subset mechanism and protect it with alignment and version
tests. Do not return a replacement view from an in-place call.

Same-shape mutations on backed input raise the existing typed package error
before writing. `transmute` has neither `copy` nor `inplace` and always returns
an independent in-memory AnnData object.

### 2.2 Positional axis identity and ordering

Introduce one positional subsetting primitive. Filter, arrange, distinct,
joins, slices, and grouped operations must propagate zero-based integer
positions end-to-end; never reconstruct axis results by labels. Duplicate
`obs_names` and `var_names` must therefore remain unambiguous.

Unless a verb explicitly sorts, survivors retain their input relative order.
Grouped filter/distinct concatenate groups in first-seen group order and keep
within-group survivor order. Grouped arrange and slices concatenate groups in
first-seen group order and apply their ordering only within each group.

### 2.3 Joins

Keep all six AnnData metadata joins. They operate on one axis and may not
duplicate or synthesize aligned records.

- Left and full joins preserve left axis order; full join still rejects every
  right-only record.
- Inner, semi, and anti joins preserve the relative order of surviving left
  records.
- Right join follows right-key order and original left order within each key,
  but rejects every right-only record.
- `unmatched="error"` rejects unmatched left axis records before output.
  `unmatched="drop"` adds no extra restriction; the selected join kind decides
  whether unmatched left records survive.
- Right-only records are rejected by `right_join` and `full_join` regardless
  of `unmatched`, because AnnData cannot synthesize matching `X`/aligned
  storage. Document this intentional dplyr divergence.
- Preserve relationship, multiplicity, suffix, and NA-match validation with
  typed errors.

### 2.4 Persistent grouping

`group_by()` resolves exactly one axis into one or more existing `obs` or `var`
metadata column names and stores a concrete `GroupSpec(axis, columns)`.
Strings, string sequences, and annplyr tidy selectors are accepted. Computed
expressions, virtual axis-name columns, matrix sources, and an empty selection
are rejected with typed selection/axis errors. `group_by()` with neither axis
returns the underlying AnnData unchanged. `group_by(add=...)` and
`group_by(drop=...)` remain deferred and must be removed from v0.3 roadmap
promises.

Build one positional `GroupPlan` per grouped public call in `O(n + g)`. It owns
integer group IDs, dtype-preserving key rows, first positions, and position
arrays. Use `sort=False`, `observed=True`, and `dropna=False`; order nonempty
groups by first appearance, include missing-value groups, and omit unobserved
categorical levels and empty groups. Use the same plan for iteration,
introspection, filter, arrange, slices, mutation, summary, count, and tally.

`group_data()[".rows"]` contains lists of zero-based integer positions in v0.3.
This intentionally replaces ambiguous axis-label lists. `group_keys()` and
summary/count key columns preserve extension/categorical dtypes.

AnnData-returning grouped verbs return `GroupedAnnData`; `summarize`,
`summarise`, `count`, and `tally` return pandas DataFrames; `ungroup()` returns
the exact underlying AnnData object. Add persistent grouped methods for:

- `filter`, `select`, `rename`, `rename_with`, `relocate`, `transmute`;
- all six joins;
- `mutate`, `add_count`, `add_tally`, `arrange`, `distinct`, and all
  `slice_*` variants;
- `pipe`.

Non-inplace grouped calls return a new wrapper around the verb result.
`copy=False` may wrap an AnnData view. Grouped `inplace=True` calls mutate the
same underlying AnnData and return the identical wrapper (`result is self`).
`pipe` passes the wrapper, including tuple-keyword piping, so grouping is not
silently discarded.

`select` automatically retains grouping columns, placing any omitted keys
first in group-spec order and otherwise respecting the user's selection order.
Grouped `transmute` likewise retains group keys. `rename` and `rename_with`
update `GroupSpec`. A key mutation evaluates the entire call with the old
`GroupPlan`, then rebuilds future grouping from final values. Dtype-safe
reconstruction scatters pandas Series/ExtensionArrays by position and must not
round-trip through `.to_numpy()`.

Grouped joins execute once globally, including joins on the non-grouped axis,
then rewrap. If a left grouping column is a non-key name collision and receives
the left suffix, update `GroupSpec` to that output name. Reject a join if its
output cannot retain every grouping column uniquely.

### 2.5 Expressions and selectors

Add a public-behaving internal `AnnplyrExpr` wrapper with:

- the underlying Narwhals expression;
- exact source-column dependencies or an opaque marker;
- known output width when available;
- scalar/row/unknown cardinality metadata sufficient for safe batching.

All annplyr expression helpers and `obs_names`/`var_names` return wrappers.
Operators, aliases, chained methods, and Narwhals namespaces must proxy through
the wrapper and preserve conservative metadata. Provide `to_narwhals()` for
explicit external interoperability. Continue accepting raw Narwhals
expressions as opaque inputs; never inspect Narwhals private attributes. An
opaque expression is evaluated alone, projects/charges the full source, and is
never batched with another assignment.

Resolve selectors against source schema before reads. In v0.3 `where()` is a
schema/dtype predicate; value-dependent predicates are unsupported and this is
a documented migration break. Provide a zero-length typed Series/schema view
to matrix `where()` predicates so selector resolution cannot read matrix data.
Preserve pandas DataFrame sources in aligned containers.

Sequential `mutate` semantics are authoritative: dependencies on a newly
created or overwritten column see the preceding result; scalar recycling and
extension dtypes remain valid. Batch only a contiguous set of assignments whose
known dependencies, output widths, and cardinalities prove they are mutually
independent and compatible. Otherwise evaluate sequentially. Reuse one
Narwhals frame across an evaluation sequence when semantics permit it.

### 2.6 Source projection and budgets

Create `_sources.py` as a clear dependency boundary. Define adapters for:

- pandas DataFrames;
- NumPy dense arrays and AnnData dense view wrappers;
- SciPy CSR/CSC sparse matrices and sparse arrays;
- backed dense datasets;
- AnnData backed `CSRDataset` and `CSCDataset` sources.

Each adapter exposes schema (names and dtypes), shape, projected reads by
integer row/column positions, and pandas conversion. Backed fancy indexing may
read sorted positions internally but must restore requested order. Sparse wide
exports use pandas sparse columns where supported. Long exports may materialize
only the selected values and never read an unselected matrix region.

Use a two-phase request planner for every public call: resolve all source
requests, compute all projections and their cumulative charge, validate the
budget, and only then invoke any adapter read. A later over-budget request must
not permit an earlier source read.

`max_matrix_values` is the cumulative count of logical projected matrix cells
delivered to expression evaluation or pandas export during one public call.
For an exact projection the charge is `projected_rows * projected_columns`.
Opaque expressions charge the full relevant source. The budget does not
estimate bytes, pandas overhead, the final long-table allocation, or aligned
AnnData storage copied solely to satisfy `copy=True`. Negative budgets fail
before reads; `None` is unbounded.

Add `max_matrix_values` to every matrix-reading expression/export API and its
grouped counterpart:

- `filter`, `arrange`, `distinct`;
- `mutate`, `transmute`, `summarize`/`summarise`;
- `pull`, `to_df`, `to_tidy`, `pivot_longer`, and `as_frame`.

Schema-only axis selection/reordering (`select(x=...)`, `rename_with(x=...)`,
`relocate(x=...)`) does not charge a matrix read. Metadata-only operations do
not expose a redundant budget argument.

Create sentinel adapters/sources whose schema and shape are readable but whose
projection/array conversion records reads. Tests must prove that invalid,
negative, and cumulative over-budget requests perform zero reads.

### 2.7 Evaluation and copying optimizations

Add virtual axis-name and row-number columns only when dependency metadata or
an opaque fallback requires them. Avoid repeated metadata-frame copies, reuse
evaluation frames, and skip no-op `obs`/`var` assignments. Do not introduce
shallow AnnData copies that share mutable aligned arrays. Keep `_verbs.py` as
orchestration; `_sources.py` and a focused `_groups.py` are justified
boundaries, while further splitting requires a demonstrated dependency
boundary.
